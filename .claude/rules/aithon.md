# Reglas del AIthon

Estas reglas aplican a todo el trabajo realizado con los agentes y skills `aithon-*` en este proyecto.

1. **Priorizar problemática local concreta.** Trabajar siempre sobre un problema específico de Tierra del Fuego (Ushuaia, Río Grande, Tolhuin, zonas rurales/antárticas), con un alcance acotado — no problemas genéricos o globales.

2. **No construir antes de definir usuario, dolor, MVP y demo.** Antes de escribir código o diseñar un prototipo, debe existir: usuario principal, dolor concreto, alcance del MVP, y una idea clara de qué se va a mostrar en la demo.

3. **Evitar datos sensibles o privados salvo que sea imprescindible.** No usar datos personales, de salud, ubicación precisa de individuos, ni información institucional confidencial a menos que sea estrictamente necesario para el MVP, y en ese caso minimizar y anonimizar.

4. **Preferir datos simulados realistas si no hay datos confiables.** Si no hay datos reales disponibles, generar datos de ejemplo realistas y marcarlos explícitamente como simulados/mockeados, tanto en el código como en la presentación.

5. **Priorizar demo funcional en pocas horas.** El objetivo es tener algo que funcione de punta a punta para mostrar, no una solución completa o una arquitectura ideal. Recortar alcance antes que dejar algo a medio terminar.

6. **Mantener cada salida concreta y accionable.** Evitar generalidades. Cada entregable (investigación, especificación, código, revisión, pitch) debe poder usarse directamente como insumo del siguiente paso.

7. **Marcar supuestos explícitamente.** Cualquier dato, contexto o decisión que no esté confirmado debe marcarse como **Supuesto:** para que el equipo pueda validarlo o ajustarlo.

8. **Revisar privacidad, sesgos, factibilidad y mantenimiento.** Antes de presentar, pasar por una revisión crítica que cubra estos cuatro puntos como mínimo, además de impacto y claridad.

9. **Preparar siempre una explicación simple para jurado no técnico.** Toda solución debe poder explicarse en pocas frases, sin jerga técnica, a alguien sin background de IA o programación.
